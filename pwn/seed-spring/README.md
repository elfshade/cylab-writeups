# CyLab — seed-sPRiNG

* **Platform:** CyLab Security Academy / picoCTF 2019 (Challenge ID: `50`)
* **Category:** Binary Exploitation / PRNG Prediction (Pwn)
* **Difficulty:** Difficulty 3
* **Date Solved:** October 2026
* **Tools Used:** Python 3, pwntools, ctypes (`libc.so.6`)
* **Binary:** `seed_spring` (32-bit x86 ELF)

---

## TL;DR

The challenge requires correctly guessing 30 consecutive pseudo-random numbers generated by `rand() & 0xf`. Rather than relying on a cryptographically secure random number generator (CSPRNG), the binary seeds the glibc linear congruential / additive feedback generator using the current UNIX epoch timestamp (`srand(time(0))`). Because `time(0)` resolution is in whole seconds, an attacker can synchronize with the remote server's timestamp, initialize a local glibc `rand()` instance via Python `ctypes`, and deterministically compute all 30 outputs in advance to trigger `get_flag()`.

## Static Analysis & Vulnerability

### 1. Decompiled Logic

Decompilation of `main()`:

```c
#include <stdio.h>
#include <stdlib.h>
#include <time.h>

void get_flag() {
    puts("Congratulations! Here is your flag:");
    system("cat flag.txt");
}

int main() {
    puts("Welcome to the Spring of Seeds!");
    srand(time(0));             // VULNERABILITY: Weak seeding via 1-second resolution timestamp

    for (int i = 1; i <= 30; i++) {
        printf("LEVEL (%d/30)\n", i);
        printf("Guess the height: ");
        
        int guess;
        if (scanf("%d", &guess) != 1) exit(-1);

        int target = rand() & 0xf;
        if (guess != target) {
            puts("WRONG!");
            exit(-1);
        }
    }

    get_flag();
    return 0;
}
```

### 2. PRNG Mechanics & Weakness

glibc's `rand()` uses an additive feedback generator (TYPE_3 linear feedback shift register). Given an identical 32-bit seed, it yields a bit-for-bit identical sequence of numbers across all platforms running glibc.

```text
           Server: srand(time(0)) at timestamp T_0
                     |
                     +---> rand() & 0xf (Level 1)
                     +---> rand() & 0xf (Level 2)
                     |       ...
                     +---> rand() & 0xf (Level 30)
                     
           Attacker: ctypes.CDLL("libc.so.6")
                     |
                     +---> srand(T_client)
                     +---> Predict identical sequence!
```

Because network latency and server clock drift are typically within $\pm 2$ seconds:
$$\text{Seed} \in [\text{Client Time} - 2, \text{Client Time} + 2]$$

By iterating through a small delta window, the seed is guaranteed to match.

## Dynamic Analysis & Exploitation Strategy

1. **Local Synchronization:**
   We load the host system's `libc.so.6` using Python's `ctypes`:
   ```python
   import ctypes, time
   libc = ctypes.CDLL("libc.so.6")
   now = int(time.time())
   ```
2. **Predicting the 30 Heights:**
   For a candidate seed `now + delta`, we call:
   ```python
   libc.srand(now + delta)
   guesses = [(libc.rand() & 0xf) for _ in range(30)]
   ```
3. **Interaction Protocol:**
   - For levels 1 through 29, the service prompts with `"Guess the height: "`.
   - On level 30, we send the final guess. Note that the program does not print another prompt after level 30; it immediately branches to `get_flag()`.

## Exploit

The complete exploit script is available at [exploit.py](exploit.py):

```python
#!/usr/bin/env python3
import ctypes, re, sys, time
from pwn import *

context.log_level = "info"
HOST, PORT = "chatelaine.cylabacademy.net", 24815
libc = ctypes.CDLL("libc.so.6")

def solve():
    # Account for slight network latency and clock jitter
    for delta in [0, 1, -1, 2, -2]:
        try:
            io = remote(HOST, PORT, timeout=5)
            now = int(time.time()) + delta
            libc.srand(now)
            guesses = [(libc.rand() & 0xf) for _ in range(30)]

            for i in range(29):
                io.recvuntil(b"Guess the height: ")
                io.sendline(str(guesses[i]).encode())

            io.recvuntil(b"Guess the height: ")
            io.sendline(str(guesses[29]).encode())

            data = io.recvrepeat(timeout=3)
            m = re.search(rb"academy\{[^}]+\}", data)
            if m:
                log.success(f"Flag captured with delta={delta}: {m.group().decode()}")
                io.close()
                return
            io.close()
        except Exception:
            continue

if __name__ == "__main__":
    solve()
```

## Key Takeaways & Lessons

1. **Insecurity of `time(0)` Seeding:** Timestamps provide negligible entropy (only 1 value per second). Any PRNG seeded with `time(0)` can be predicted in real time.
2. **Deterministic glibc `rand()` State:** glibc's standard PRNG is fully deterministic and platform-reproducible. Calling `libc.srand()` and `libc.rand()` directly via `ctypes` replicates remote execution exactly.
3. **Handling Socket Stream Termination:** In multi-round challenges, the final round often prints the winning output without presenting another prompt. Exploit loops should anticipate the termination condition rather than waiting on timeouts.
